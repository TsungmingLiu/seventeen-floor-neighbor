## 2. 已確認的關係與尚未決定的整合

- 若晴由羽球團獨立認識男主；不再是雨澄表姊，也不預設認識其他女主。
- 映雪與男主是大學時交往過的初戀。畢業後因工作異地，曾嘗試維持，最後分開；重逢後要重新認識現在的彼此，不自動復合。
- 映雪不採「男主新工作的同事／主管」入口，也不採許棠的合作舊識設定。她仍保留自己的策略顧問職業，不藉此替男主決定轉職。
- 若晴與映雪不是姊妹，沒有預設好友或親屬關係。新舊女主未來可以因實際事件認識，但不自動共享筆名、戀情或玩家選擇。
- 舊候選的撤回維持不變，不另設替身或第三候補。

**仍待決定：** 新路線從開頭、中段或後篇接入；是否及如何延長探索期；四人同輪可選的範圍；重逢場合；分手的具體城市、年份、交往時長、雙方當年受傷的細節。不得把推薦過的 T2、同學聚餐、男主換工作或某種分手責任分配自動升格為既定事件。這些留白不阻擋成年當下的形象設定。

## 3. 四種不同的戀愛體驗

| 角色 | 主要魅力與相處樂趣 | 感情成長曲線 | 自己需要面對的缺點 |
| --- | --- | --- | --- |
| 許棠 | 日常默契、不明說的偏愛、細微幽默；普通小事逐漸成為共同習慣 | 住得近 → 相處自在 → 願意讓對方參與自己的生活 | 太快收回求助，用「我自己來」隔開別人 |
| 江雨澄 | 同頻後的私人同盟；作品、遊戲、奇怪堅持和熟後靈動的吐槽 | 興趣交集 → 確認被尊重 → 主動分享內在世界 | 興趣上有主見，面對自己的感情卻可能退回含糊或沉默 |
| 林若晴 | 玩伴感、一起行動和出糗、小勝負心；會主動分享眼前的快樂 | 一起玩得開心 → 特別想留時間給你 → 也能一起安靜 | 太快帶大家往前走，忘記確認別人的步調，也不及早說自己累了 |
| 沈映雪 | 熟悉與陌生交錯的成年重逢；清醒的欣賞與明確的選擇 | 舊熟悉／吸引可能先回來 → 發現現在的陌生 → 重建信任與共同未來 | 想好再說，容易讓重要的人最後才收到結論；也可能沿用過期的了解 |

差異是主要反應與形成親密的方法，不是禁止共享特質。四人都能笑、主動、生氣、安靜或犯錯；不能把一人固定成熱情、一人固定成冷臉。映雪的前史不賦予她感情優先權，其他三人的關係不是她的過渡選项。

## 4. 人設驗證標準

1. **同場景辨識：** 面對店沒開、散場還想多待、男主不同意她等普通情境，不靠姓名／職業／口頭禪，也應看出不同的關注點和反應。這是後續檢查要求，不是本輪已取得 QA PASS。
2. **拿掉傷痛仍討喜：** 移除工作危機、家庭壓力與分手傷痛，普通一次相處仍要有讓人想再見她的理由。
3. **換人不能照搬：** 可共用場景，不能只換名字就把心動、衝突與修復原封不動搬給另一人。
4. **雙向且不完美：** 各自有生活、需求與選擇；不是男主的情緒服務者，也不是正確對話選項的考官。
5. **不複製成同一條壓力線：** 不以「工作累積 → 崩潰 → 男主安慰」當四人的共同結構。

## 5. 名字的自然意象

名字只作輕量彩蛋：棠的花木與春意、雨澄的雨後澄明、若晴的晴日、映雪的冬日雪光。這是命名聯想，不是嚴格四季分類，不硬把雨澄配給秋天；不強制雪天分手、初雪重逢或生日／服裝季節。冬意也不等於映雪是等待男主融化的冰山。

- 各人物文件擁有明確標示的背景、個性與已批准設計方向；不擁有 scene ordering、route/state、既有台詞或 accepted reference pixels。
- 現行許棠／雨澄的 scene、continuity、knowledge、角色 JSON、designVersion 與圖包 authority 不變。若後續創作發現與既有 locked artifact 衝突，依 `.ai/policies/SOURCE_AUTHORITY.md` 處理，不得默默折衷。
